1. Definition

Not a Chatbot. Not a Workflow.

An Autonomous Decision-Maker.

Chatbot

  • • Stateless Q&A
  • • Single turn
  • • No tools, no memory

Workflow Automation

  • • Predefined steps
  • • Deterministic
  • • No reasoning

AI Agent

  • Perceives → Reasons → Acts
  • Uses tools
  • Holds state
  • Adapts to outcomes

"An AI agent is software that uses an LLM to decide what to do next, calls tools to act, and adapts based on results — autonomously pursuing a goal."

Agents handle data-heavy execution while humans focus on strategic oversight.

The LLM: Brain of the Agent

The core reasoning engine and the rules that guide it.

What the LLM Does

  • ✓ Interprets natural language input
  • ✓ Reasons about goals and constraints
  • ✓ Decides which tool to call (or none)
  • ✓ Generates structured output (JSON, text)
  • ✓ Synthesizes results into final response

System Prompt

= Values & Instincts

  • • Defines agent identity, role, tone
  • • Sets boundaries: what to do and not do
  • • Instructions hierarchy (system > user)
  • • Includes tool descriptions & schemas
  • • Like prefrontal cortex: constrains impulse
"The LLM is the cortex. The system prompt is your values and instincts — it doesn't think for you, but it shapes every thought."

Memory Systems

Short-term, Long-term & Vector DB Embeddings

Short-term Memory

Working Memory

  • • Conversation history in context window
  • • Current tool call results
  • • Scratchpad / chain-of-thought
  • • Lost when session ends
Analogy: A messy desk for your active project.

Long-term Semantic

Hippocampus → Cortex

  • • Facts & knowledge stored in DB
  • • User preferences, past summaries
  • • Persists across sessions
  • • Requires explicit write/read
Analogy: A filing cabinet for saved information.

Episodic + Vector DB

Associative Memory

  • • Records of past interactions
  • • Stored as embeddings in vector DB
  • • Retrieved by similarity, not exact match
  • • Enables pattern-based recall
Analogy: A smell triggering a childhood memory.
Compaction Process

Managed transition from short-term to long-term memory. Triggered automatically to prevent running out of context window space.

A reviewing LLM acts as a smart filter: extracts key facts, resolves conflicts, and permanently saves only condensed data.

Vector Databases

Search by meaning instead of exact keywords. Text becomes a high-dimensional vector array.

A mathematical similarity search finds closest matching memories (e.g., searching "holiday" retrieves "vacation" notes).

Deterministic Tools

  • • API calls (search, CRUD, payments)
  • • Database queries (SQL, graph)
  • • File operations (read, write, parse)
  • • Calculations and data transforms

  • • Summarization of retrieved docs
  • • Classification / sentiment analysis
  • • Code generation or review

Security Critical Autonomously executing code introduces obvious risks. Sandbox environments (Docker), set strict resource limits/timeouts, and explicitly whitelist allowed libraries.

RAG Architecture

Retrieval-Augmented Generation: "Reading notes" instead of memory alone.

1

Ingestion

Docs → Chunks → Embeddings → Vector DB
2

Retrieval

Query → Similarity Search → Top-K → Reranking
3

Generation

Retrieved Chunks + Query → LLM → Answer w/ Citations

Key Design Decisions

  • Chunk size? 200-800 tokens. Smaller = precise. Larger = context-rich.
  • Embedding model? Match to your domain. General vs. fine-tuned.
  • Retrieval method? Dense (vector), sparse (BM25), or hybrid.
  • Reranking? Cross-encoder reranker improves top-K quality.
  • Citations? Return source metadata with chunks. Let LLM cite.
The Nervous System

MCP

Model Context Protocol

The Problem

Every tool has a different integration pattern. Auth, schemas, and errors are all ad-hoc.

N agents × M tools = N×M custom integrations

The Solution

Standard protocol for tool discovery + invocation. Consistent auth, schemas, permissions.

State & Planning Patterns

How agents track progress and decide what to do next.

State = Body Posture

  • • Tracks where the agent is in a task
  • • Session state: current conversation
  • • Task state: progress through steps
  • • Enables pause, resume, and handoff

Planner = Decision-Making

  • • Decides what to do next and order
  • • Executor = carries out steps
  • • May plan full upfront or step-by-step
  • • Handles replanning when surprised

ReAct

Think → Act → Observe, one step at a time.

Simple but can meander.

Plan-and-Execute

Generate full plan → execute steps sequentially.

Structured but rigid.

DAG Workflows

Predefined graph of steps. LLM at decision nodes.

Most predictable.

Safety & Guardrails

The Immune System: Protecting the agent and the world from each other.

INPUT Guardrails

  • Prompt injection detection
  • Input validation & sanitize
  • Rate limiting & abuse detect
  • Content classification (PII)

EXECUTION Guardrails

  • Tool permission scoping
  • Cost & token budgets
  • Max iteration / loop limits
  • Human-in-the-loop points

OUTPUT Guardrails

  • Response valid (format)
  • PII redaction
  • Confidence thresholds
  • Audit logging
Rule of thumb: Build guardrails before you ship, not after the incident.
Vital Signs

Evaluation & Observability

You can't improve what you can't measure.

What to Trace

  • Every LLM call: prompt, completion, latency, tokens
  • Every tool call: name, params, result, duration
  • Decision points: why choose tool X?
  • Full trace: complete chain of steps per task
  • Errors: what failed, where, why

Key Metrics

  • Task completion rate: did it finish?
  • Correctness/accuracy: was it right?
  • Cost per task: tokens × price
  • Latency: end-to-end, per step
  • Failure rate by type: hallucination, loop, error

Evaluation Approaches

Unit tests (tools) Integration tests (flows) Objective evals (code-based) Subjective (LLM-as-judge) Human eval (edge cases)

What Goes Wrong

Six common agent failure modes and how to fix them.

Hallucination

LLM fabricates facts, tool names, or API responses.

FIX: RAG grounding + output validation

Tool Misuse

Wrong tool selected, bad params, or called when unneeded.

FIX: Clear schemas + few-shot examples

Prompt Injection

Malicious input overrides system instructions.

FIX: Sanitization + instruction hierarchy

Stale Memory

Agent acts on outdated context or old retrieved data.

FIX: TTLs on memory + freshness checks

Runaway Loops

Agent keeps retrying same failed action indefinitely.

FIX: Max iteration limits + loop detection

Cost Blowups

Long chains → many LLM calls → surprise bills.

FIX: Token budgets + cost monitoring

Specialized agents working together like a company.

Sequential

The Assembly Line

Agent A finishes task → hands output directly to Agent B. Highly predictable and easy to debug.

Parallel

Independent Tasks

Multiple agents work at exactly the same time. Final agent combines outputs. Reduces latency.

Manager-Led

Hierarchical Team

Design Principles for Reliability

  • 1. Rigid Data Schemas: Handoffs (e.g., JSON formats) break more often than models. Define them strictly.
  • 2. Tool Scoping: Give each agent ONLY the specific tools it needs. Keeps system secure and debuggable.

For complex, multi-step workflows mapping as literal graphs.

Practical Guidance

When NOT to use an agent:

  • • Task is fully deterministic (use script)
  • • No decision-making needed (use pipeline)
  • • Errors catastrophic / unrecoverable
  • • Simple prompt + LLM is enough

Minimal Viable Agent (MVA)

  • • 1 LLM + 1 System Prompt + 2-3 Tools
  • • RAG only if docs are involved
  • • Single-turn first, add memory later
  • • Add guardrails BEFORE capabilities

Pre-Launch Checklist

Production-readiness verification

10-Point Readiness

  • Clear goal defined (what is 'done'?)
  • LLM selected & system prompt written
  • Tools defined (schemas + permissions)
  • RAG pipeline built if docs involved
  • Memory strategy (short + long-term)
  • Guardrails on input, execution, output
  • Max iterations and cost budgets set
  • Observability: traces + metrics active
  • Eval suite (unit, integration, judge)
  • Human-in-the-loop for destructive ops

Default Guardrails

  • ♦ Max 10 tool calls per task
  • ♦ Token budget per run (e.g. 50K)
  • ♦ No destructive ops without confirmation
  • ♦ PII detection on all inputs/outputs
  • ♦ Prompt injection filter on input
  • ♦ Timeout: 60s per tool, 5m per task
  • ♦ Fallback: escalate to human on 2 fails
  • ♦ Log every LLM call and tool invocation
